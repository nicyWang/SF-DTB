# 桌面AI搭档 · 需求-架构复盘（2026-08-22）

> 目的：停止补丁式开发，从需求出发重新确立架构，一次把地基打对。

---

## 一、需求（从汪总历次表述提炼）

### 核心定位
**全天候桌面 AI 办公搭档**——不是玩具桌宠，是能真干活的生产力工具。

### 功能需求（按优先级）

| 级别 | 需求 | 汪总原话/场景 |
|---|---|---|
| P0 | 一句话任务执行 | "整理桌面""放首歌""设闹钟""关掉XX""浏览器搜索" |
| P0 | 自然语音对话 | 连续多轮、可打断、听得准、回得快 |
| P0 | 有温度的表达 | 表情跟回复情绪、语音带情感 |
| P1 | 屏幕理解与操控 | 看得到屏幕、点得准按钮、完成后有真凭实据 |
| P1 | 记忆与性格 | 记住主人习惯、性格随交互演化 |
| P2 | 直播弹幕互动 | 抖音直播场景 |
| P2 | 多形象 | 云朵兔毛毛等可切换 |

### 非功能需求
- 响应：语音说完到她开口 ≤3s
- 可靠：核心链路成功率 ≥95%，失败要有兜底而非沉默
- 可维护：改一个功能不牵动全身（当前做不到）

## 二、现状盘点（事实，非评价）

### 代码规模
| 层 | 行数 | 说明 |
|---|---|---|
| 主进程 main/ | 2,400 | 工具执行/窗口/托盘/TTS通道 |
| 渲染层 src/core/ | 8,886 | 状态机/语音/渲染/记忆/性格 |
| vendor 引擎 | 1,953 | emotion-ball 官方引擎 |
| **合计** | **≈13,000+** | 三天内在 voice.js/pet.js 上反复加补丁 |

### 复杂度热点（问题源头）

1. **渲染器 6 套并存**：sprite / ball / emotionBallRenderer / live2d / avatar-live / videoSprite
   - 历史层积：Live2D→自绘ball→官方emotion-ball，旧的没删
2. **工具两套命名并存**：`list_dir`（旧snake_case）与 `list-dir`（新kebab-case）同时注册，37个工具实际能力重复约1/3
3. **语音链路组合爆炸**：
   - 2 条引擎链（豆包端到端 / 自建管线）
   - 自建管线内：3 种 ASR 模式 × PCM/webm 双录音路径 × EBML 自愈 × 回声防护 × 代际令牌
   - TTS 4 级降级：豆包→Edge→智谱→系统
   - **组合数 > 30 种路径，测不过来，bug 温床**
4. **配置项 27 个** localStorage 键，互相依赖关系隐式（如 ASR 凭证藏在豆包配置里）
5. **服务商标配遗留**：智谱（欠费弃用）、Edge TTS、火山全家桶并存

### 三天 bug 复盘规律
- 80% 的 bug 发生在**降级路径**和**状态切换**上（EBML、PCM节点、双循环、重复播报）
- 每个补丁平均引入 1-2 个新 bug
- 根因：**路径太多 + 状态隐式**，不是某一处代码写错

## 三、目标架构（收敛原则：每环节一条主路，降级显式且少）

### 3.1 总分层

```
┌─ 交互层 ─────────────────────────────┐
│ 语音(豆包WS) / 文字输入 / 菜单       │
├─ 大脑层 ─────────────────────────────┤
│ 豆包 LLM（chatWithTools 单一入口）   │
│ 意图路由：任务类→工具 | 聊天类→直答  │
├─ 能力层 ─────────────────────────────┤
│ 工具执行器（统一命名，去重后~25个）  │
│ 屏幕操控（AX树优先+索引点击+验证器） │
├─ 表达层 ─────────────────────────────┤
│ 表情：emotion-ball（唯一渲染器）     │
│ 语音：豆包TTS（情感参数）            │
├─ 记忆层 ─────────────────────────────┤
│ 记忆/性格/知识（保留现有，接口不动） │
└──────────────────────────────────────┘
```

### 3.2 语音链路（收敛前后对比）

**现在**：2引擎 × 3ASR × 2录音 × 4TTS = 30+ 路径
**目标**：
```
主路（95%场景）：豆包实时WS —— 听+断句+识别 服务端包办
  ↘ 拿到文本 → 豆包LLM(带工具) → 豆包TTS(情感)
兜底（WS断连时）：自建VAD→PCM→火山ASR（保留现有已修稳链路，仅此一条）
```
- 客户端不再做音频格式处理（webm/EBML 路径**删除**）
- TTS 降级只留：豆包 → 系统 afplay（Edge/智谱删除）

### 3.3 渲染器收敛
- **保留**：emotionBallRenderer（官方引擎，表情丰富）
- **删除**：ball.js(708行)、sprite.js(1088行)、live2d.js(368行)、videoSprite.js(287行)、avatar-live.js
- 旧立绘资产归档不删文件，代码路径移除
- 预计净删 **≈2,500 行**

### 3.4 工具收敛
- 统一 kebab-case 命名，删除 snake_case 旧别名
- 合并重复能力（list_dir/list-dir、click系/mouse系合并）
- 37 → 约 25 个，SPEC 与实现一一对应

### 3.5 状态机显式化（pet.js 瘦身）
pet.js 1511 行是最大风险点。拆分为：
```
pet/
├── index.js        # 装配（<200行）
├── conversation.js # 对话流程（chat/voiceChat）
├── emotion.js      # 表情状态机
├── tasks.js        # 屏幕任务回路（CUA）
└── events.js       # 事件路由
```

4. **直播弹幕**：P2 暂缓，还是保留现状不动？
